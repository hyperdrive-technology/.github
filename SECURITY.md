# Security policy

## Supported versions

Security fixes target the `main` branch of each repository. Older releases and
development branches are not separately supported.

## Report a vulnerability

Use GitHub private vulnerability reporting in the affected public repository:

- [Holodeck](https://github.com/hyperdrive-technology/holodeck/security/advisories/new)
- [Holodeck SDK](https://github.com/hyperdrive-technology/holodeck-sdk/security/advisories/new)
- [Org community files](https://github.com/hyperdrive-technology/.github/security/advisories/new)

Open the repository's **Security** tab and choose **Report a vulnerability**
when available. Private reporting must be enabled in repository settings; this
policy does not enable it. See
[GitHub's private reporting guide](https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/report-privately).

If private reporting is unavailable, contact the maintainers via GitHub by
opening an issue that only requests a private security reporting channel.
Do not include vulnerability details in that issue. Maintainer:
[@DezLitz](https://github.com/DezLitz).

For private core, collaborators should request a private reporting channel from
the maintainers in that repository. GitHub private vulnerability reporting and
repository security advisories are features of public repositories.
Maintainers with the required permissions can create a draft security advisory
in a public repository to coordinate a fix.

In the private report, include the affected repository and commit or version,
reproduction steps or a minimal proof of concept, likely impact, and any known
workaround. Remove credentials and personal data from attachments. Keep the
report private while maintainers investigate and agree on disclosure.
